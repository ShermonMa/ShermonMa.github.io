Background

Most “AI helps you search” tools on the market are one-shot Q&A: ask once, answer once, and next time you start over. Meanwhile, everyone has many topics they care about, and as the AI era arrives the overhead of keeping track only grows. So the topics that truly matter — a technology, an event, a competitor — need continuous tracking: subscribe once and forget about it, and every day automatically turn the incremental progress — “what wasn’t there yesterday but appeared today” — into a daily, weekly, or monthly report.

OtterScout is built for exactly this: subscribe to any topic in one sentence, and every morning Otto delivers a diff report that covers only the new progress.

What I did

Designed and built the full pipeline solo, iterated over 49 pain-point-driven batches:

  • Natural-language subscriptions: turn a vague one-sentence topic into an executable multi-source collection plan, with subscription-goal filtering, major-update few-shot examples, and targeted retrieval on user-designated focus sites.
  • Multi-agent exploration subsystem: a TopicSeeker runs a first-round overview search and differentiates sub-topics into a pool; a NewsSearcher per sub-topic runs multi-turn conversational retrieval, deciding on its own whether to continue and what to search next; newly discovered topics are reviewed, deduped, and flowed back into the pool — a closed loop of “exploration spawning more exploration”.
  • 3-tier dedup: URL-hash idempotent dedup → hybrid recall (vector cosine 0.7 + FTS5 BM25 0.3) with an LLM consistency review → full-text shingled dedup (3000-char windows, 100 overlap), catching “partial duplicates” like reposts, rewrites, and retitled articles at sub-item granularity.
  • Event clustering + diff report: cluster incremental items into events, compare against history, and output only “new progress”.
  • Strict citation (anti-hallucination): every fact carries numbered citations; out-of-bounds citations are rejected at the program layer; uncited sentences are dropped outright.
  • Fixed pipeline: orchestrated with LangGraph StateGraph plus SqliteSaver checkpoints — evaluable, cost-predictable, fault-localizable, and automatically resumed after process interruption with idempotent persistence.

Technical highlights

  • Tiered, engineered LLM access: a unified Gateway routes HIGH/MID/LOW tiers (provider/model swappable via env, with a fallback chain); none of the 20+ LLM call sites touches a model SDK directly. An 83-line unified classification skeleton covers 5 scenarios (outcome classification, goal filtering, consistency review, etc.). Prompt prefix-cache discipline (fixed instructions first, variable parameters last) hits DeepSeek’s server-side KV cache, with per-call-site cache-hit usage logging.

  • Dynamic induction tree + evolution timeline: facing a flood of news under one topic, maintain a “topic → multi-level themes → events” induction tree with B+ tree-style invariants (≤4 branch children, ≤10 leaf children; violations trigger LLM split/merge and recursive upward checks). Every organization pass ends with a pure-SQL shape audit (fan-out overflow / mixed levels / dangling or self-referencing parents / ungrouped backlog) that triggers a full rebalance when anomalies are found; the taxonomy package has zero project dependencies. Paired with an evolution timeline, reports are generated automatically.
  • Crash recovery & idempotency: on desktop, users killing the process is the norm — the check graph carries SqliteSaver checkpoints, and interrupted runs resume automatically on restart; single-transaction persistence plus INSERT OR IGNORE on unique constraints means re-running any node never duplicates data. Also fixed the subtle bug where checkpoint serialization deep-copied state and lost in-batch event_id references — resolved by mapping drafts to persisted IDs via content keys.
  • Desktop process lifecycle & energy saving: a standalone timer service is the sole owner of the backend Python process — it reads the DB every 30s for due topics and dispatches serially, reclaims an idle backend after 30 minutes, and pre-warms 5 minutes before the next due check. Fixed a desktop-specific failure where the spawned backend’s stdout pipe filled its 64KB buffer and the blocked flush froze the uvicorn event loop, hanging every API.
  • Daily report generation: when a day has more than 20 updates, an LLM first ranks them by importance (the returned id set is validated for exact equality — reordered or hallucinated ids fail outright), partial digests are written in batches of 20 and recursively merged; the stored structured content is then deterministically rendered to Markdown (no LLM involved), so the same data always renders the same document. Major updates trigger email notifications.

  • Evolvable storage: the MVP runs on a single-file SQLite + sqlite-vec + FTS5 stack (CJK unigram tokenization for Chinese) with zero service dependencies — ideal for desktop distribution — and can later migrate smoothly to PostgreSQL + Qdrant.

Results

  • 49 pain-point-driven iteration batches, each with a plan document and a delivery report; schema migrated to v20, all 20 migrations idempotent and covered by migration tests.
  • 534 tests green, with LLM / embedding / search / SMTP all stubbed — the entire suite never touches the network and runs fully offline.

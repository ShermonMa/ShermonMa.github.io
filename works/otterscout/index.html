背景

市面上的「AI 帮你搜资料」大多是一次性问答：问一次、答一次，下次还得重来。同时，每个人感兴趣的话题可能有很多，随着AI时代来临，记忆统筹工作会变得更多，因此很多真正重要的话题——某个技术、某个事件、某个竞争对手——需要的是持续追踪：订阅之后不用管，每天自动把「昨天没有、今天新出现」的增量进展制作成日报、周报、月报汇报。

Otter Scout就是为此做的：一句话订阅任意话题，Otto每天清晨汇报一份只讲新进展的 diff 日报。

我的工作

独立设计与实现全流程，历经 49 个痛点驱动批次迭代：

  • 自然语言订阅：把模糊的一句话话题，转化为可执行的多源采集计划；支持订阅目标过滤、重大更新举例（FewShot）与重点关注网站定向检索。
  • 多 agent 探索子系统：TopicSeeker 首轮概况检索后分化子话题入池；NewsSearcher 对每个子话题做多轮对话检索，自主决定继续/停止与下一查搜什么；检索中发现的新话题经评审去重后回流池中继续派发，形成「探索中产生新探索」的闭环。
  • 三级判重：URL hash 幂等去重 → 向量余弦 0.7 + FTS5 BM25 0.3 混合召回 + LLM 一致性评审 → 全文 3000/100 滑窗分片判重，以亚条目粒度识别转载、改写、换标题的「部分重复」。
  • 事件聚类 + diff 日报：把增量内容聚成事件、与历史比对，只输出「新进展」。
  • 引用强约束（防幻觉）：每条事实带编号引用，越界引用在程序层校验、无引用句直接丢弃。
  • 固定 Pipeline：LangGraph StateGraph 编排 + SqliteSaver 检查点，可评估、成本可预测、故障可定位，进程中断后自动续跑且落库幂等。

技术亮点

  • LLM 三档可调配 + 工程化收口：统一 Gateway 做 HIGH/MID/LOW 三档路由（provider/model 均可 env 替换、带降级链），全项目 20+ 处 LLM 调用点无一处直连模型 SDK；83 行统一分类骨架收口五分类/目标过滤/一致性评审等 5 类场景；prompt 前缀缓存规范（固定指令在前、变量收尾）命中 DeepSeek 服务端 KVCache，并按调用点记录缓存命中用量。
  • 动态归纳树 + 时间演变轴：面对一个主题下的海量新闻，维护「话题 → 多级主题 → 事件」的归纳树：B+ 树式不变量（树枝子节点 ≤4、叶子 ≤10，超限触发 LLM 分裂/归并并递归向上检查），每次归纳收尾跑纯 SQL 形状自检（扇出超限/同层混合/悬空自指环/未归纳淤积），命中异常自动全量 rebalance 纠偏；归纳树为零项目依赖的独立包。配合时间演变轴描述事态发展，自动生成报告。
  • 崩溃恢复与幂等设计：桌面端用户直接关机是常态——check 图挂 SqliteSaver 检查点，重启后扫描残留任务自动续跑；persist 单事务 + 唯一约束 INSERT OR IGNORE，任意节点重跑不产生重复数据。修过「检查点序列化深拷贝导致批内 event_id 引用丢失」的隐蔽坑，改为按草稿内容键映射解析。
  • 桌面端进程生命周期与节能体系：独立计时器服务全权掌管后端 Python 进程的开关——每 30s 读库算到期任务、串行按时分发，闲置 30 分钟自动回收、到期前 5 分钟提前预热；修过「spawn 的后端 stdout 管道写满 64KB 缓冲、flush 阻塞 uvicorn 事件循环致全接口假死」的桌面端特有故障。
  • 日报生成：当日更新超 20 条时先 LLM 按重要性排序（返回 id 集合全等校验，乱序/幻觉 id 直接判失败），20 条/批分别撰写再递归汇总成一份；落库后把结构化内容确定性渲染为 Markdown（不调 LLM），同一份数据永远渲染出同一份文档；重大更新触发邮件通知。
  • 存储可演进：MVP 用 SQLite + sqlite-vec + FTS5（中文走 CJK 单字分词）单文件落地，零服务依赖即可分发桌面端，后续也可平滑迁移到 PostgreSQL + Qdrant。

成果

  • 49 个痛点驱动批次迭代，每批次都有计划文档与交付报告；schema 迁移至 v20，20 个版本迁移全部幂等且各配迁移测试。
  • 534 个测试全绿，LLM / embedding / 搜索 / SMTP 全部 Stub 注入，全程不触网，无网环境也能跑完整测试。
  • 项目仍在持续迭代，这会是我的第一个长期维护项目。希望它能帮助我，帮助大家更快地获取信息，增强与世界的联结和感知。

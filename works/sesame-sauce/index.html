SesameSauce · 视频网站

Go + Vue 全栈视频网站，四层领域架构，支持 HLS 多码率转码流播与全文检索。

背景

本项目旨在串联后端常用中间件，模拟高并发视频软件，按https://www.bilibili.com/的规格精心复刻，并部署于阿里云ECS。处理了视频上传、转码、切片流播、全文检索、点赞计数等一整套带状态、带异步流水线的系统。把一堆基础设施（MySQL / Redis / Kafka / Elasticsearch / 对象存储 / FFmpeg）组织成可演进、可替换的工程结构。

我的工作

全栈实现，前后端分离：

  • 前端（Vue 3.5）：Composition API + <script setup>，Vite 8 构建，Element Plus 组件库，hls.js 播放 m3u8 流，Axios + Vue Router。
  • 后端（Go）：Gin + GORM，四层架构（Handler / Application / Domain / Infra）。
  • 视频处理：FFmpeg / FFprobe 转码、封面生成、视频分析，经 Kafka 异步投递。
  • 存储与检索：MinIO 对象存储 + Elasticsearch 全文搜索 + Redis（含 RedisBloom Cuckoo Filter 去重 / 计数器缓存）。

技术亮点

  • 领域层零基础设施依赖：domain/ 只定义端口契约（VideoStorage、VideoAnalyzer、CoverGenerator、VideoTranscoder、SearchIndexer 等六个端口），不 import 任何具体技术包；infra 实现附带编译期校验（var _ domain.VideoStorage = ...），通过依赖倒置实现可替换——例如把 MinIO 换成阿里云 OSS，只需新增一个端口实现。
  • 应用层编排：串联多个领域操作完成完整用例（如：创建视频 → 生成预签名 URL → 投递 Kafka 事件），并负责跨 DAO 事务与 DTO 转换。
  • HLS 多码率转码：FFmpeg 转出 1080p/5000k 与 360p/800k 双码率并生成 master.m3u8，前端 hls.js 自适应切换；转码流程设计幂等，避免 Kafka 重复消费导致的重复处理。
  • 双桶对象存储与并发上传：原视频入私有桶、预签名 URL 直传；HLS 产物入公有桶（预签名无法覆盖 m3u8 的子分片请求）。转码产物由 8 并发 worker pool 上传，任一分片失败即整体取消。
  • 点赞链路全异步化：点赞经 Kafka 削峰，per-user-per-video SetNX 短锁防重；Cuckoo Filter + Redis pending + DB 三级判重；消费侧仅在 DB 变更时经 Lua 脚本原子同步 Redis 计数；另有 30s 兜底 flush 任务扫描 ZSet 脏数据直接落库，失败重试进入死信。
  • 计数器缓存体系：点赞/播放等计数采用 base + delta 双层设计——请求只写 Redis delta，刷盘任务按「60s 定时或脏列表 ≥1000」混合触发，GETDEL 原子清零 delta，配合 Redis 分布式刷盘锁防并发刷盘；失败回滚 delta 并重试，3 次后进入死信 Hash。
  • 多级缓存防御：Redis 缓存视频详情、播放记录、点赞记录。TTL 离散抖动防雪崩；SetNX 互斥锁 + Lua 脚本原子释放，单请求回源 DB 防热点 Key 击穿；Cuckoo Filter 拦截非法 key 防穿透。
  • 检索降级：ES 召回 hashid 后回 MySQL 排序分页，ES 故障自动降级为 LIKE 模糊查询；启动时幂等创建索引与升级 mapping。
  • 成体系的并发优化：WaitGroup 并行化散见全链路——创建视频双预签名并行、确认上传双 HEAD 并行、未读数 5 条查询并行、消费侧 DB 写入与 ES 索引并行；写库统一只 Update 指定列，规避 GORM Save 全字段覆写的竞态。
  • ID 混淆与鉴权：Hashids 对外暴露不可枚举的视频 / 用户 ID；JWT 用户鉴权；读扩散模型实现系统通知推送，支持点赞、评论消息通知。

成果

  • 一套完整可运行的视频网站，覆盖上传、转码、流播、搜索、互动。
  • 清晰的四层架构与端口契约，基础设施可平滑替换。
